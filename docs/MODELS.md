# MODELS.md

Database schema (Supabase Postgres). Source of truth for the data model.
Every change ships as a migration in `server/supabase/migrations/`.

Model ownership follows the module boundaries in `ARCHITECTURE.md` §2.2 — each table below
names the module that owns it. **Only the owning module's repository may query its table.**
Other modules go through that module's `*.interface.js`.

---

## 0. Conventions

- **Primary keys:** `uuid default gen_random_uuid()`. Real UUID columns generated by
  Postgres, not `varchar(36)` filled in by application code.
- **Ownership:** every user-owned table carries
  `user_id uuid not null references auth.users(id) on delete cascade`, even where it could
  be reached via a join. Repository methods scope on it directly.
- **Timestamps:** `created_at` / `updated_at timestamptz not null default now()`,
  `updated_at` maintained by a trigger.
- **Enums:** Postgres `create type`, not free-text.
- **Casing:** columns are `snake_case`. The API speaks `camelCase` — the conversion is the
  job of the shared serialization transform (`shared/dto.js`), applied uniformly. No module
  hand-writes a mapping.
- **RLS:** enabled on every table as defence in depth (§3), but **it is not the primary
  authorization boundary** — the repository layer is.

### `live_sessions` — module: `live-session`  *(transient)*
The mutable counterpart to `meetings`, backing the real-time stretch feature. Short-lived by
design; see `ARCHITECTURE.md` §3.3.

| Column | Type | Notes |
| --- | --- | --- |
| `id` | `uuid` PK | |
| `user_id` | `uuid` | |
| `socket_id` | `text` null | current connection; refreshed on reconnect |
| `title` | `text` | |
| `meeting_date` | `date` null | |
| `state` | `live_session_state` | default `'active'` |
| `chunk_count` | `int` default 0 | |
| `running_transcript` | `text` default `''` | appended per chunk |
| `rolling_summary` | `jsonb` null | replaced wholesale each refresh |
| `meeting_id` | `uuid` null | set once materialized into a durable `Meeting` |
| `expires_at` | `timestamptz` | `now() + interval '4 hours'`, extended on activity |
| `created_at` / `updated_at` | `timestamptz` | |

Index: `(state, expires_at)` for the sweeper.

**Lifecycle.** `active` → (`live:end`) → materialize → `ended` with `meeting_id` set.
A periodic sweeper picks up `active` rows past `expires_at`, materializes whatever exists,
and marks them `expired`. If there is no usable transcript, the resulting meeting is marked
`failed` with a readable message. A dropped connection must never silently lose a recording.

`running_transcript` and `rolling_summary` are working state. Once materialized they are
redundant with `transcripts` / `summaries` and may be nulled out.

## 3. Row Level Security

Enable on every table. The pattern, repeated for `meetings`, `transcripts`, `summaries`,
`summary_points`, `speakers`, `action_items`, `live_sessions` — this is why `user_id` is
denormalized onto all of them:

```sql
alter table meetings enable row level security;

create policy "own_meetings_all" on meetings
  for all using (auth.uid() = user_id) with check (auth.uid() = user_id);
```

`profiles`: select/update own row only.

**Important:** the backend connects with the service-role key, which **bypasses RLS
entirely**. These policies protect only against a leaked anon key or direct client access.
The real authorization boundary is the repository layer:

```js
// Every repository method is scoped by userId. There is no unscoped read.
async function findById(id, userId) {
  const { data } = await supabase
    .from('meetings').select('*')
    .eq('id', id).eq('user_id', userId)   // never omit this
    .maybeSingle();
  return data;
}
```

A repository method without a `userId` parameter should not pass review.

## 4. Storage

Bucket `recordings`, **private**.

Path: `{user_id}/{meeting_id}/{original_filename}`.

```sql
-- Users may only touch objects under their own uid prefix.
create policy "own_recordings" on storage.objects
  for all using (
    bucket_id = 'recordings'
    and (storage.foldername(name))[1] = auth.uid()::text
  );
```

Uploads use short-lived signed upload URLs issued by `config/upload.js`. Playback uses
signed download URLs (1 hour). Deleting a meeting must delete the storage object too —
the `meeting:deleted` event handler does this; Postgres cascade does not reach Storage.

## 5. Search

History search covers title + transcript + summary overview. Wrap it in a Postgres function
so the query lives in a migration, not in a template string inside a repository:

```sql
create or replace function search_meetings(
  p_user_id uuid, p_q text, p_from date, p_to date, p_limit int, p_offset int
) returns setof meetings language sql stable as $$
  select m.*
  from meetings m
  left join transcripts t on t.meeting_id = m.id
  left join summaries  s on s.meeting_id = m.id
  where m.user_id = p_user_id
    and (p_q is null or
         m.title ilike '%' || p_q || '%'
         or t.search_vector @@ plainto_tsquery('simple', p_q)
         or s.overview ilike '%' || p_q || '%')
    and (p_from is null or m.meeting_date >= p_from)
    and (p_to   is null or m.meeting_date <= p_to)
  order by m.created_at desc
  limit p_limit offset p_offset;
$$;
```

The `meeting` repository calls it via `supabase.rpc('search_meetings', …)`. A matching
`count_meetings(...)` function supplies `meta.total` for the pagination envelope.

Note the join reaches `transcripts` and `summaries`, which other modules own. This is the
one accepted exception, contained inside a database function rather than in module code —
document it here rather than letting it spread.

## 6. Migration checklist

1. `server/supabase/migrations/<timestamp>_<name>.sql` — forward-only, never edit an
   applied file.
2. Table **+ indexes + `enable row level security` + policies in the same migration.**
   A table shipped without RLS is publicly readable by anyone holding the anon key.
3. `npx supabase db push`
4. Update this file in the same commit.
